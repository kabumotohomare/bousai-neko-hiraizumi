- **作成日:** 2026-08-28
- **目的:** `Basic_specifications.md` / `Development_specifications.md` の未確定事項（特に13章・8.3章）を、実際に動くプロトタイプで検証した結果に基づいて更新するための材料をまとめる
- **検証方法:** Three.js製の簡易プロトタイプ（2D猫えらび→3Dみまわり→リザルト）を作成し、調整パネルで各種数値・演出をリアルタイムに切り替えながら比較した

## 1. 数値バランス（最重要・要修正）

### 問題
仕様書デフォルト値（`territoryRadius=300m` / `playerMoveSpeedMps=2.2` / `gameDurationSec=90`）で計算すると、

```
最大移動距離 = 2.2m/s × 90s = 198m
縄張り直径   = 300m × 2 = 600m
到達可能割合 = 198 / 600 ≈ 33%
```

制限時間をフルに使っても縄張りの3分の1程度しか移動できない。実際にはヒントを見る・点検する・迷うといった時間も消費するため、体感の到達範囲はさらに狭くなる。これは「9.3の未確定事項」以前の、数値設計そのものの不整合。

### 検証結果
プロトタイプの調整パネルで半径・速度・時間を可変にして試したところ、以下の組み合わせだと「縄張りの端まで一往復できる」感覚が得られた。

| パラメータ | 現行仕様 | MVP暫定推奨案 |
|---|---|---|
| `territoryRadius` | 300m | **60〜80m**（暫定70m） |
| `playerMoveSpeedMps` | 2.2 | 2.2〜2.4 |
| `gameDurationSec` | 90 | 90 |
| 最大移動距離 / 直径 | 33% | 約150%（余裕を持って探索可能） |

> 半径を縮めるか、速度・時間を上げるかはプロダクト側の意図（「広い町を感じてほしい」か「短時間で遊びきれる」か）に関わる意思決定なので、上記は暫定値として提示する。ただし**この不整合を残したままMVP実装に進むと、初回プレイで迷って何も点検できずに終わる体験になりやすい**ため、実装着手前に必ず数値を確定させることを推奨する。

**反映先:** `Basic_specifications.md` §13.4（スコア設計の前提として）、§9.2 `cats.json` の `radius` サンプル値／ `Development_specifications.md` §10.3 `game-config.json` のデフォルト値、§23-1

## 2. 移動方式（13.1 の検証結果）

プロトタイプで3方式を実装し、比較した。

| 方式 | 操作 | メリット | デメリット |
|---|---|---|---|
| **戦車型**（1本スティック） | 上下=前後、左右=旋回 | 実装が単純、方向感覚を保ちやすい | 旋回中は視界が回転するため慣れが必要 |
| **自由移動**（1本スティック） | 倒した方向へ直接移動、視点固定 | 直感的 | 「自分が今どちらを向いているか」が分かりにくい |
| **タップ移動** | 地面をタップ→自動で歩く | 視界の流れが少なく最も酔いにくい | 操作の主体感・没入感が下がる |

### 推奨
- **基本操作は「戦車型」を採用**（視点回転を伴うが、方向感覚を保ちやすく実装も軽い）
- **「タップ移動」を、画面酔いしやすい人向けの代替モードとして選択制で用意**することを推奨。設定画面または初回選択で切り替えられるようにする
- 「自由移動」は方向感覚の面で他2方式に劣るため、採用しない方向で良さそう

**反映先:** `Basic_specifications.md` §13.1（結論を記載）、§7.2「操作仕様」／`Development_specifications.md` §8.3「操作仕様」、§23-1

## 3. 画面酔い対策の具体仕様（13.2 の検証結果）

既存方針（カメラ揺れ禁止・急旋回禁止・低速）に加え、以下を実装して比較した。

| 対策 | 内容 | 所感 |
|---|---|---|
| **移動・旋回中のビネット** | 動いている間だけ画面端を暗くし、静止すると戻す | 効果を体感しやすく、実装コストも低い。**採用推奨** |
| **移動中の動的FOV** | 速く動くほどFOVを最大10度狭める | ビネットほど劇的ではないが違和感もない。**採用推奨（弱め設定で）** |
| **ヒゲアンカー（固定基準点）** | 画面下中央に鼻とヒゲを常設表示。旋回方向へ最大±5度傾ける | 「今どちらを向いているか」の手がかりとして機能し、世界観にも合う。**採用推奨** |
| **旋回速度の上限** | 上限値をパラメータ化 | 上限が高すぎると酔いやすいことを確認。デフォルトは2.0〜2.5 rad/s程度を推奨 |
| **タップ移動（代替操作）** | 上記2章参照 | 酔いやすい人向けの独立オプションとして有効 |

**反映先:** `Basic_specifications.md` §4.2「認知負荷・画面酔い対策方針」に具体策として追記、§13.2に確定案として記載／`Development_specifications.md` §16.3「カメラ」に追記、`game-config.json` に以下のキーを追加提案:

```json
{
  "vignetteEnabled": true,
  "dynamicFovEnabled": true,
  "whiskerAnchorEnabled": true,
  "turnSpeedRadPerSec": 2.4,
  "comfortMoveModeAvailable": true
}
```

## 4. 縄張り境界の視覚表現

### 問題
現行仕様は「境界外に出ようとしたら押し戻し＋メッセージ」のみで、境界に到達するまで場所が分からない。

### 検証結果
地面に半透明のリングを常時描画したところ、「壁にぶつかって初めて気づく」体験から「近づいていることが事前に分かる」体験に変わった。実装コストも低い（リング状メッシュ1枚）。

**推奨: 境界リングを常時（または一定距離まで近づいたら）表示する。**

**反映先:** `Basic_specifications.md` §7.2「縄張り制限」に追記／`Development_specifications.md` §8.3「縄張り制御」、§16.2「オブジェクト」

## 5. HUD表示項目の追加

### 問題
現行仕様のHUDは「残り時間・点検数・スコア」のみで、「あと何基残っているか」が分からず目標感が薄い。

### 推奨
「点検数」を「点検数 / 総数」の分数表示に変更する（例: `🚒 2 / 6`）。

**反映先:** `Basic_specifications.md` §7.2「表示要素」／`Development_specifications.md` §8.3「表示要素」

## 6. 初回成功体験の配置（13.9 の検証結果）

プロトタイプでは、猫の初期位置から約3m以内に必ず1基の消火栓を配置し、開始直後にほぼ確実に1基目を点検できるようにした。「何もできないまま終わる」プレイヤーを防ぐ効果が期待できる。

**推奨: 猫ごとの初期配置に「スポーン地点から半径5m以内に最低1基」というルールを設ける。**

**反映先:** `Basic_specifications.md` §13.9、§9.1「消火栓データ」／`Development_specifications.md` §17「バッチ/公開データ生成仕様」（抽出ルールに追記）

## 7. 操作UIレイアウト

プロトタイプでは以下の配置で検証した。

- 移動スティック: **画面中央下**（当初は左下だったが、片手操作時の親指位置を検証するため中央に変更して比較中）
- 「てんけんする」ボタン: 右下（据え置き）
- ヒゲアンカー: 画面中央下、スティックのやや上に重ねて表示

中央配置は左右どちらの手でも届きやすい反面、「てんけんする」ボタンとの同時操作（移動しながら点検）の親指の移動距離が伸びる可能性がある。**この点は実機・複数人でのテストが必要**で、今回のプロトタイプ検証だけでは結論が出ていない。

**反映先:** `Basic_specifications.md` §7.2「表示要素」（パッド位置の記述を「左下」から要検討に変更）／`Development_specifications.md` §8.3「操作仕様」
