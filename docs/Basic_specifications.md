## 1. エグゼクティブサマリー

**「ぼうさいネコ＠平泉」は、岩手県平泉町のオープンデータ（消火栓の位置情報）と、市民からの野良猫目撃情報を活用した、スマートフォン向けの地域参加型・防災3DアクションWebゲームである。**

プレイヤーは平泉町に暮らす猫となり、自分の縄張りの中を90秒間見回って消火栓を見つけ、点検アクションを行う。ゲームは、Leaflet.js による2Dマップで猫と縄張りを選び、その後 Three.js による軽量3D空間で実際に見回る、**2D選択 → 3D体験**の二段構成とする。

本作の目的は、単なるスコア獲得ゲームではなく、**「遊びながら地域の消防水利の位置を覚える」こと**と、**「住民参加でゲーム世界が育つこと」**の両立にある。したがって、ゲーム設計においては以下を重視する。

1. **防災学習としての意味づけ**
   - 点検行動をスコアだけで終わらせず、「地域の安全確認に参加している」という文脈をプレイヤーに返す。
2. **認知負荷の低い初期体験**
   - 猫目線3Dの魅力は維持しつつ、初回プレイ時の迷い・酔い・操作負荷を抑える。
3. **住民参加による世界の更新**
   - 野良猫報告が `cats.json` 更新を通じてゲームへ反映され、新しい猫や縄張りが増えていく。
4. **完全ノンログイン運用**
   - 高齢者・子ども・観光客でもすぐに触れるよう、ログインなしで開始でき、進行状況は `localStorage` に保存する。

## 2. プロダクトゴール

### 2.1 目指す価値

本作は、子どもから高齢者までが楽しく遊べるゲーム体験を通じて、平泉町の消防水利施設（消火栓）の場所を自然に覚えられるようにすることを目指す。また、住民の猫目撃情報がゲーム世界に反映されることで、地域参加型の情報循環を生み出し、**防災 × ゲーミフィケーション × まち参加**のWebアプリケーションとして成立させる。

### 2.2 成功状態の定義

- プレイヤーが「どこに消火栓があるか」を遊びながら覚えられる
- 初回プレイ時に迷いすぎず、短時間で楽しさを理解できる
- 住民報告が新しい猫・縄張りとしてゲーム内に反映される
- ノンログインでも継続プレイできる
- スコア競争だけでなく、地域貢献の意味を感じられる

## 4. 体験設計の基本方針

### 4.1 プレイヤーの動機づけ方針

プレイヤーの報酬は、単なる「点数」だけに依存させない。点検成功時やリザルト画面では、以下のような**防災学習・地域貢献の意味づけ**を行う。

- 「この消火栓の場所、通学路でも思い出してみよう」
- 「きょうの見回りで ○件の消火栓を確認した」
- 「みんなの見回りが、町の安心につながる」

これにより、行動の意味を補強し、外発的報酬だけに依存しない継続動機を形成する。

### 4.2 認知負荷・画面酔い対策方針

猫目線3Dは本作の魅力だが、スマホでの自由移動は認知負荷や画面酔いを招きやすい。そのため、初期実装では**「気持ちよさ」よりも「迷わなさ・酔いにくさ」優先**とする。

基本方針:
- カメラの上下動・揺れ・急旋回を抑制する
- 初回プレイでは誘導を強める
- 移動速度は速すぎない値から開始する
- 必要に応じて「誘導ルートあり」と「自由探索」を段階解放する

### 4.3 フィードバックの即時性

「てんけんする」操作に対しては、入力から視覚反応、スコア反映までを短く保つ。押したのに反応が遅いと報酬感が落ちるため、演出は短く、状態更新は即時とする。

## 5. ユーザーストーリー

### 5.1 プレイヤー

- **地元の小学生**
  - ログインなしで始められる
  - 猫になって知っている町を見回る楽しさがある
  - 後日、現実の町で「あの消火栓だ」と気づける

- **観光客**
  - 平泉の街並みを猫目線で探索できる
  - 一般的な観光とは異なるローカルな体験が得られる
  - 防災設備の位置を知ることで地域理解が深まる

### 5.2 情報提供者

- **散歩中の高齢者**
  - 会員登録なしで猫を報告できる
  - 自分の報告がゲームの猫や縄張りに反映される
  - 家族や地域への貢献感を得られる

- **地域住民**
  - 通勤・生活の中で気づいた猫情報を手軽に共有できる
  - 子どもたちの遊びや学びに役立っている感覚を得られる

### 5.3 運営者

- 投稿を確認し、反映可否を判断する
- `cats.json` を更新し、猫や縄張りを追加・調整する
- 必要に応じて不適切投稿や重複投稿を除外する

## 6. システム構成とデータ連携

```text
【情報提供者】
  └─ 外部フォームから猫の目撃情報を送信
        ↓
【運営者】
  └─ 内容確認・採用判断
  └─ cats.json 更新
        ↓
【Webアプリ】
  ├─ 2Dマップ画面で猫を選択
  ├─ 3D見回り画面で消火栓を点検
  └─ localStorage に進行状況を保存
        ↓
【プレイヤー】
  └─ 更新された猫・縄張りを体験
```

### 6.1 想定技術構成

- フロントエンド: HTML / CSS / JavaScript
- 2Dマップ: Leaflet.js
- 3D描画: Three.js
- データ配信: 静的ファイル配信（例: GitHub Pages 等）
- 外部投稿: Googleフォーム等
- 保存先: `localStorage`

## 7. 機能仕様

## 7.1 画面1：2D猫えらび画面

### 目的
プレイヤーが見回りに使う猫を選び、その縄張りを理解したうえで3D画面へ入ること。

### 表示要素
- 平泉町の2Dマップ
- 猫ピン
- 選択中の猫カード
  - 猫の名前
  - 簡単な紹介文
  - 縄張りサイズの概略
- 「このねこでみまわりスタート」ボタン

### 挙動
- 猫ピンをタップすると、その猫の縄張りを地図上に半透明表示する
- 選択中の猫カードを更新する
- スタート押下時、選択地点を中心にズーム演出を行い、3D画面へ遷移する

### UX要件
- スマホ片手操作を前提とする
- 猫未選択時はスタートボタンを非活性にする
- 初見でも「どの猫を選べばよいか」が直感的に分かること

---

## 7.2 画面2：3Dみまわり画面

### 目的
プレイヤーが猫目線で縄張りを移動し、消火栓を見つけて点検すること。

### ゲームルール
- 制限時間は **90秒** とする
- プレイヤーは選択した猫の縄張り内のみ行動できる
- 消火栓に近づくと「てんけんする」ボタンが有効化される
- 点検済みの消火栓は再点検不可、または再点検しても加点なしとする

### 表示要素
- 上部: 残り時間、点検数、スコア
- 左下: 仮想移動パッドまたは簡易十字キー
- 右下: 「てんけんする」ボタン
- 中央付近: 必要に応じて簡易ガイド表示

### カメラ・移動仕様
- カメラは低い位置の猫目線に置く
- ただし上下揺れや左右ブレは最小限に抑える
- 急激なカメラ回転を避ける
- 画面酔い対策のため、初期版ではジャンプ・高速旋回・過度な視点操作は採用しない

### 初回体験の配慮
- 初回プレイでは最初の1基目まで視覚誘導を入れてよい
- 必要に応じて「かんたんモード（誘導あり）」を設ける
- プレイヤーが迷い続ける状態を避けるため、一定時間点検がない場合はヒント表示を行ってよい

### 縄張り制限
- 縄張り外に出ようとすると進行を止める
- その際、以下のキャラ文言を表示する
  - **「ここからそとは、ぼくのなわばりじゃない」**
- 単なる透明壁ではなく、軽い押し戻しや演出を伴ってもよい

### 点検アクション
- 消火栓の近くで「てんけんする」を押すと、点検成功演出を再生する
- 演出は**短く、達成感があり、入力反応が早い**ことを優先する
- 表現方針としては、現実の消火栓の造形を保ちながら、**宝箱が開くような気持ちよさ**を感じる演出を目指す
- 具体演出候補:
  - 接続口キャップが開く
  - 光やキラキラのエフェクトが出る
  - スコアがポップ表示される
  - 軽い効果音を鳴らす

### 点検成功後の状態
- その消火栓は視覚的に「点検済み」と分かる状態に変わる
- 例: チェックマーク、光の消灯、色変化、足跡マークなど

---

## 7.3 画面3：おさんぽ完了画面（リザルト）

### 遷移条件
- 90秒経過時に終了する
- 必要に応じて全点検達成時の早期終了は今後検討可とする

### 表示内容
- 点検した消火栓の数
- スコア
- 見回りコメント
- 防災学習・地域貢献の文脈を持つメッセージ
- 新しい猫や縄張り更新がある場合の案内

### メッセージ方針
リザルトでは、単に「何点だった」ではなく、プレイヤーの行動が地域理解につながったと感じられる文言を入れる。

文言例:
- 「きょうのみまわりで、○件の消火栓をたしかめた」
- 「この場所、ほんとうの町でも思い出せるかな」
- 「みんなの見回りが、町のあんしんにつながる」

### アクション
- 「もういちど遊ぶ」
- 「べつのねこで遊ぶ」
- 「ねこの もくげきほうこくをする」

## 7.4 住民報告連携

### 基本方針
住民による猫目撃情報は、ゲーム内で直接即時公開するのではなく、**外部フォーム → 運営確認 → データ更新**の運用とする。

### 想定入力項目
- 猫の写真（任意または必須は要検討）
- 目撃場所
- 目撃日時
- 猫の特徴メモ（毛色、柄など）

### 反映フロー
1. 住民が外部フォームから報告
2. 運営者が内容確認
3. 採用時に `cats.json` を更新
4. Webアプリ再読込時に新猫または縄張り変更を反映

### 注意点
- プレイヤー体験と情報提供体験は役割が異なるため、UI導線は分ける
- 「報告すればすぐ反映」ではなく、「確認のうえ反映」と明記する

## 8. 造形・演出仕様

## 8.1 消火栓モデル方針

平泉町の地上式消火栓をモチーフにし、現実の学習対象として識別できる外見を維持する。

### 必須特徴
1. 赤系の本体
2. 円柱ベースの本体シルエット
3. 側面の接続口
4. キャップまたは蓋の存在が分かる構造
5. 必要に応じて「消火栓」表記

### デフォルメ方針
- 完全リアル志向ではなく、スマホ描画負荷と視認性を優先する
- 遠くからでも「消火栓」と認識できることを重視する
- 点検時の気持ちよさを出すため、演出面では軽い誇張を許容する

## 8.2 世界表現

- 建物は軽量な簡易モデルを基本とする
- 地名やエリア名は必要に応じてビルボード表示する
- リアルさよりも「迷いにくさ」「位置把握しやすさ」を優先する

## 9. データ仕様

## 9.1 消火栓データ

### 入力元
- 平泉町オープンデータ `13.消防水利施設一覧.csv`

### 利用項目
- 緯度
- 経度
- 必要に応じて名称・識別子

### 利用方法
- 緯度経度からゲーム内平面座標 `(X, Z)` に変換する
- 対応する消火栓オブジェクトを3D空間に配置する

## 9.2 猫データ `cats.json`

```json
[
  {
    "id": "cat_001",
    "name": "シラヤマ",
    "display_area_name": "志羅山地区",
    "status": "unlocked",
    "center": [38.987472, 141.115946],
    "radius": 300,
    "info": "志羅山地区でよく見られる黒猫。住民報告により縄張り拡大中。",
    "last_updated": "2026-08-25"
  }
]
```

### 項目補足
- `id`: システム内識別子
- `name`: 表示名
- `display_area_name`: プレイヤー向けの地域名表示
- `status`: 解放状態
- `center`: 縄張り中心座標（緯度・経度）
- `radius`: 縄張り半径（m想定）
- `info`: 紹介文
- `last_updated`: 更新日

## 9.3 クライアント保存データ `localStorage`

```json
{
  "inspected_hydrants": ["1-1", "1-2"],
  "unlocked_cats": ["cat_001", "cat_002"],
  "played_tutorial": true,
  "last_selected_cat": "cat_001"
}
```

### 保存方針
- サーバー側個人アカウントは持たない
- 端末依存であることを前提にする
- ブラウザデータ削除時は進行も消える

## 10. 非機能要件

### 10.1 対応環境
- スマートフォンWebブラウザを最優先
- 主要対象は iPhone / Android の近年標準ブラウザ
- PCは運営確認用または簡易閲覧用とし、プレイ最適化対象はスマホ優先

### 10.2 パフォーマンス
- 軽量描画を最優先する
- 古めの端末でも大きな破綻なく動くことを目標とする
- 初期目標は **30fps以上を維持できる構成** とする
- 重いポストエフェクトや高密度メッシュは避ける

### 10.3 可用性
- 通信失敗時は再試行または分かりやすい再読み込み案内を出す
- データが一部取得できない場合は、可能な範囲で遊べる縮退動作も検討する

### 10.4 アクセシビリティ
- ボタンは十分な大きさを確保する
- 小さな文字や低コントラストを避ける
- 子どもや高齢者でも理解しやすい、やさしい言い回しを使う

### 10.5 プライバシー
- 住民報告では個人情報の取得を最小限にする
- 詳細住所や本人特定情報は扱わない方針とする
- 写真投稿がある場合は、第三者や私有地情報の写り込みに注意する

- カメラ回転の上限
- 移動速度
- 視点揺れの有無
- 感度設定の要否

### 13.3 点検演出の方向性
- リアル寄り（接続口キャップ開閉中心）
- ゲーム的演出寄り（光・ポップ・効果音強め）

### 13.4 スコア設計
- 1基あたり固定加点か

### 13.5 リザルトメッセージの出し分け
- 点検数に応じて変えるか
- 初回／再プレイで変えるか

### 13.6 チュートリアル要否
- 初回に操作説明画面を出すか
- プレイ中オーバーレイで説明するか
- 完全説明なしでUI誘導のみとするか

### 13.7 縄張り形状
- 単純な円形半径で扱うか
- 将来的にポリゴン形状へ拡張するか

### 13.8 座標変換仕様
- 緯度経度からローカル座標への変換式
- 原点の定義
- スケールの統一ルール

### 13.9 初期解放コンテンツ
- 最初から遊べる猫の数
- 初期縄張りの広さ
- 初回プレイで必ず成功体験が得られる配置にするか

### 13.10 住民報告フォーム仕様
- 写真を必須にするか
- 位置入力を地図選択にするか文章入力にするか
